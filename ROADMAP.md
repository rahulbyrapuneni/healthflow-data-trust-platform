# Roadmap

## Sprint 0 — Foundation
- Define the business problem
- Define users and success measures
- Select the minimum viable stack
- Define quality dimensions and rules
- Create the repository structure
- Create the first data generator

## Sprint 1 — Healthcare Data Simulator
- Generate related patient, appointment, lab, claim, and insurance datasets
- Add controlled defects
- Add configurable record counts
- Produce a data-generation summary
- Add reproducibility through a fixed seed

## Sprint 2 — Data Quality Engine
- Schema validation
- Completeness checks
- Validity checks
- Uniqueness checks
- Referential integrity checks
- Temporal consistency checks
- Clinical plausibility checks

## Sprint 3 — Trust Scoring
- Severity levels
- Dataset-level scores
- Domain-level scores
- Overall trust score
- Trend history
- Root-cause categories

## Sprint 4 — Analytics Layer
- DuckDB ingestion
- Curated tables
- Quality issue marts
- SQL views
- KPI queries

## Sprint 5 — User Interface
- Streamlit quality dashboard
- Dataset overview
- Rule results
- Issue drill-through
- Downloadable remediation report

## Sprint 6 — Local AI Assistance
- Optional Ollama integration
- Plain-language issue summaries
- Suggested remediation steps
- Natural-language questions over quality results

## Sprint 7 — Engineering Quality
- Unit tests
- Integration tests
- Docker
- GitHub Actions
- Documentation
- Demo video
- LinkedIn case study
